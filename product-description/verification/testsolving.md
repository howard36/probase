# Verification: testsolving

How to run this file: load the [fixtures](README.md#fixtures) before starting, and again after every item whose Setup says "reload the fixtures afterwards" (any item that edits a permission, a problem, a collection or a user in the database, or gives a fixture user another testsolver type or a new membership). The items use `ts` "Testsolve Lab" (Integer answers, requires testsolving, authors shown), `aime` "AIME Lab" (the three-digit box; `A1`, answer `42`, difficulty 1), `demo` (no testsolving) and `topsoj` (forced Serious, reached through the `join-topsoj` invite). In `ts`, `A1` (answer `2`), `C1` (answer `$\sqrt{2}$`), `A2` (answer `6`) and `N2` (answer `7`) have difficulty 1 and a 10-minute limit, and are the problems timed items use; `N1` (answer `2`) has difficulty 2 (15 minutes) and `G1` has none; every `ts` problem is Wes Writer's and `A1`, `N1` and `A2` are in the test "Mock Contest #1" at `/c/ts/t/mock-contest-1-1`. `A2`'s leaderboard holds Sue Serious's solve (one wrong answer, 1:40); `N2`'s holds seven fixture users named Crowd 1 to Crowd 7 (ids `u-crowd1` to `u-crowd7`): Crowd 2, 4 and 6 solved with no wrong answer in 2:00, 4:00 and 6:00, Crowd 1, 3 and 5 with one wrong answer in 1:00, 3:00 and 5:00, and Crowd 7 did not solve after three answers, so the full ranking is Crowd 2, 4, 6, 1, 3, 5, then Crowd 7 unranked. A started attempt is permanent, so reset the user before any item whose Setup says "no attempt": for Sam Serious run `delete from "SolveAttempt" where "userId" = 'u-serious'` (he has none in the fixtures); for Sue Serious `delete from "SolveAttempt" where "userId" = 'u-serious2' and "problemId" <> {ts A2}`; and before any item whose Setup says Uma Unchosen has "no type" (she is the only member without one, and confirming uses her up) `update "Permission" set "testsolverType" = null, "seriousTestsolverStartedAt" = null where "userId" = 'u-unchosen' and "collectionId" = {ts}`. A Setup of "Sam Serious in a running attempt on `ts` `A1`" means: reset Sam, open `/c/ts/p/A1`, press "Start testsolving", and submit nothing unless the Setup says so. Run SQL with `psql` against the verification database only; in it, `{ts}` stands for `(select id from "Collection" where cid = 'ts')` and `{ts A1}` for `(select p.id from "Problem" p join "Collection" c on c.id = p."collectionId" where c.cid = 'ts' and p.pid = 'A1')`, and likewise for other problems. Timed items never wait out a limit: they move the attempt's `startedAt` back in the database, and after that the tester must not reload unless the step says so, because the open page keeps the deadline it loaded with while the server judges by the database (the grace-buffer items depend on exactly that). "Delete the session cookie" means removing `authjs.session-token` for `localhost` in the browser's devtools (Application, Cookies); "view source" means the source of a full page load (Ctrl+U), which holds everything the server sent. The Device column names the fixture role signed in, as in the README's [Devices and conditions](README.md#devices-and-conditions): `serious` is Sam Serious, `serious2` Sue Serious, `casual` Cal Casual, `unchosen` Uma Unchosen, `writer` Wes Writer, `admin` Ada Admin, `viewer` Vic Viewer, `stranger` Stan Stranger; `+` joins a second role in a second browser context; `second tab` is the same user in another tab of the same context; `slow server`, `offline`, `narrow`, `keyboard`, `screen reader`, `prod build` and `hand` are the README's conditions, and in this file `hand` also covers devtools network throttling set to "Slow 3G" (which delays the page's refresh as well as its actions) and a browser clock set away from the server's (a browser on another machine, or Playwright's `page.clock.setSystemTime`).
